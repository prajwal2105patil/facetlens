# Ablation: bare vs enriched retrieval text

Same embedding model (`all-MiniLM-L6-v2`), same reference set, same K.
The only variable is the string that gets embedded for each facet.
Generated by `python -m src.pipeline ablation`; no LLM calls involved.

## Recall on facets the reference says SHOULD be scored

A miss here is a real loss - the facet never reaches the scorer.

| 15 | 10/19 (53%) | 10/19 (53%) |

## Recall on facets the reference says should be ABSTAINED

A miss here is harmless: a non-observable facet that is never retrieved costs nothing, whereas one that is retrieved must still be gated. Lower is mildly better, and certainly not worse.

|---:|---|---|
| 10 | 5/36 (14%) | 5/36 (14%) |

| 25 | 7/36 (19%) | 8/36 (22%) |

## Verdict

Across 6 values of K, enriched retrieval text beats bare names on should-score recall **2 times**, loses **1 times**, and ties **3 times**.

Enriched text wins more often than it loses, but **not uniformly**. This is a weaker result than the decision was originally made on.

### What this corrects

The enriched text was adopted on the strength of one measured example, where it pushed `FSH level` from cosine 0.110 - tied with a genuine leadership facet - down to -0.005, and dropped `Nationality` from rank 4 to rank 5. That measurement was real and is reproducible.

This wider test shows it did **not** generalise into a clear aggregate recall improvement. The honest reading: enriching the text reliably *demotes obviously irrelevant medical and demographic facets*, which is what the single example measured, but that is not the same as surfacing more of the right facets, which is what this table measures. The two were conflated when the decision was made.

The choice is kept because demoting non-observable facets out of the candidate set is independently useful - it reduces what the observability gate has to catch - and because it costs nothing at run time. But it is recorded as a **weakly supported** decision, not a validated one.

### The result that matters more

Neither variant is good enough. Both leave roughly a third of should-score facets unretrieved at K=25, and even at K=100 neither exceeds 84%. Retrieval quality - not retrieval text formatting - is the real bottleneck, which is why it is named as the primary limitation in README and the first item in 'with another day'.
